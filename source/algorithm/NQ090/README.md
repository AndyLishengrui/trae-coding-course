# NQ090 思路分析

## 问题描述
林克需要将一个长为w、宽为h的矩形黄金蛋糕人马切成m块小矩形蛋糕，每块蛋糕的长和宽均为整数。经过m-1次切割后，计算最后得到的m块小蛋糕中，最大的那块蛋糕的面积下限。

## 思考过程
这是一个典型的最小化最大值问题，我们需要找到一种切割方式，使得最大的蛋糕块面积尽可能小。对于这种问题，我们可以使用记忆化搜索（深度优先搜索+动态规划）来解决。

## 算法思路
使用记忆化搜索（DFS + 记忆化）来求解：

1. **状态定义**：`minMax[w][h][cnt]` 表示将w×h的矩形切成cnt+1块时的最小最大面积
2. **递归终止条件**：
   - 如果当前矩形面积小于需要的块数（w*h < cnt+1），返回无穷大（无法分割）
   - 如果不需要切割（cnt=0），返回当前矩形面积
   - 如果已经计算过当前状态，直接返回记忆化的值
3. **状态转移**：
   - 尝试所有可能的竖切位置，将矩形分成左右两部分
   - 尝试所有可能的横切位置，将矩形分成上下两部分
   - 对于每种切割方式，递归计算左右（或上下）两部分的最小最大面积
   - 取所有可能切割方式中的最小值作为当前状态的结果
4. **记忆化存储**：将计算结果存储起来，避免重复计算

## 关键点编码逻辑

1. **记忆化数组**：使用三维数组`minMax[w][h][cnt]`来存储已经计算过的状态，避免重复计算，提高效率

2. **切割方式**：
   - 竖切：将矩形分成宽度为i和w-i的两部分
   - 横切：将矩形分成高度为j和h-j的两部分

3. **块数分配**：对于每一种切割方式，尝试将cnt-1次切割分配给左右（或上下）两部分，找到最优的分配方式

4. **最小值计算**：对于每种切割方式，计算左右（或上下）两部分的最大面积，然后取所有可能中的最小值

## 时间复杂度

- **时间复杂度**：O(w×h×m×(w+h))，其中w是宽度，h是高度，m是块数
  - 每个状态(w, h, cnt)需要计算一次
  - 对于每个状态，需要尝试O(w+h)种切割方式
  - 对于每种切割方式，需要尝试O(m)种块数分配方式

- **空间复杂度**：O(w×h×m)，需要一个三维数组来存储记忆化的结果

## 输入输出示例

### 输入样例
4 4 4
4 4 3
0 0 0

### 输出样例
4
6

### 解释
- 当w=4, h=4, m=4时，最优切割方式是十字斩，将蛋糕分成4块2×2的小蛋糕，最大面积为4
- 当w=4, h=4, m=3时，最优切割方式是先竖切将蛋糕分成3×4和1×4的两部分，然后将3×4的部分横切分成3×2和3×2的两部分，最大面积为6
