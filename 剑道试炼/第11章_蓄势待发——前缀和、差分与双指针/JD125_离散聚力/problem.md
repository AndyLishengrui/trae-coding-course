# JD125：离散聚力

> **AcWing 802** | 第11章 · 蓄势待发 | 知识点：离散化、前缀和

## 题目描述

赵晴儿指着一条无限长的数轴："坐标从负无穷到正无穷，但真正有值的位置只有几个。如果开一个那么大的数组，太浪费了。"

"所以要把这些稀疏的大坐标映射到连续的小下标上——这就是离散化。"梁嘉峰接话，"映射之后再用前缀和，就能 O(1) 回答区间求和的查询。"

"先聚力于有用之处，再一击命中。"

假定有一个无限长的数轴，初始每个坐标上都是0。先进行 n 次操作，每次将位置 x 上的数加 c。然后进行 m 次查询，每次求区间 [l, r] 的和。

## 输入格式

第一行两个整数 n 和 m。

接下来 n 行，每行两个整数 x 和 c。

接下来 m 行，每行两个整数 l 和 r。

## 输出格式

m 行，每行一个整数。

## 样例

输入：

```text
3 3
1 2
3 6
7 5
1 3
4 6
7 8
```

输出：

```text
8
0
5
```

## 解题思路

### 思考过程

坐标范围可能很大（比如 10^9），但真正有值的位置只有 n 个，查询涉及的位置也只有 2m 个。如果开一个 10^9 大小的数组，内存爆了。核心问题是：如何在不浪费空间的情况下，对"稀疏的大坐标"做前缀和？

答案是离散化——把真正用到的坐标收集起来，排序去重，然后映射到 1、2、3……这样的连续下标。比如坐标 [1, 3, 7] 映射到 [1, 2, 3]，原来间隔巨大的坐标变成了紧凑的数组。

### 关键洞察

离散化的步骤：

1. **收集所有用到的坐标**：n 个操作的位置 x，以及 m 个查询的 l 和 r，全部放进一个列表。
2. **排序 + 去重**：得到一个有序的、无重复的坐标集合。
3. **映射**：用二分查找（或哈希表）把原始坐标映射到下标。坐标 1 -> 下标 0，坐标 3 -> 下标 1，坐标 7 -> 下标 2。
4. **在映射后的数组上前缀和**：正常做加法和前缀和即可。
5. **查询时**：把 l 和 r 也映射到下标，然后在前缀和数组上 O(1) 查询。

### 边界情况

- 查询区间 [l, r] 内没有任何操作点：前缀和之差为 0，正确。
- l 或 r 恰好等于某个操作点：映射后前缀和正确包含该点的值。
- 多个操作作用于同一个坐标 x：在离散化数组中它们会叠加到同一个下标上，正确。
- l > r（虽然题目通常保证 l <= r）：如果出现，结果应该是 0 或负数，需注意题意。
- 坐标可能为负数：排序去重时自然处理，不影响正确性。

### 复杂度解释

- **时间 O((n + m) * log(n + m))**：排序去重需要 O(k * logk)，其中 k = n + 2m（所有坐标总数）。m 次查询每次二分查找 O(logk)。总共 O(k * logk)。
- **为什么不是 O(坐标范围)**：如果直接用原始坐标做数组下标，需要 O(坐标范围) 的空间和时间。离散化把"坐标范围"压缩为"有用坐标的数量"，当坐标稀疏时效率提升巨大。
- **空间 O(n + m)**：离散化数组和前缀和数组的大小都是有用坐标的数量。
